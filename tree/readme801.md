# 최소 비용 신장 트리(MST) 알고리즘 비교

정점 50개인 가중치 무방향 연결 그래프(희소: 간선 100개, 밀집: 간선 600개)에서 인접 리스트 + Kruskal, 인접 행렬 + Prim으로 MST를 구하고 메모리와 실행시간을 측정했다.
아래 수치는 `./mst_compare 12345`(시드 12345)로 실행한 결과이다. 난수는 직접 구현해서 같은 시드면 같은 그래프가 만들어진다. 실행시간은 실행할 때마다 조금 달라진다.

## 측정 방법

- **그래프**: 무작위 신장 트리(49개 간선)로 연결을 먼저 보장한 뒤 나머지 간선을 중복·자기 간선 없이 추가했다. 가중치는 1~100의 양의 정수이다. 희소 그래프는 Case 1과 3에서, 밀집 그래프는 Case 2와 4에서 같은 그래프를 사용했다.
- **메모리**: `sizeof`로 계산했다. 난수 생성용 임시 배열과 출력은 제외했다.
  - Kruskal = 인접 리스트(헤드 배열 + 노드 `2E`개) + 간선 배열(`E`개) + Union-Find + MST 결과 간선 49개
  - Prim = 인접 행렬(`int 50×50`) + `visited`, `key`, `parent` 배열 + MST 결과 간선 49개
- **실행시간**: 그래프 생성이 끝난 뒤 MST 계산 시작부터 끝까지만 측정했다. Kruskal은 리스트에서 간선 꺼내기, 정렬, Union-Find 과정을 모두 포함한다. 한 번의 실행이 너무 짧아서 10,000번 반복한 평균을 `clock()`으로 구했고, 4가지 경우 모두 마이크로초(us) 단위이다.
- **검증**: 그래프가 연결 그래프인지, 리스트와 행렬이 같은 그래프인지, MST가 간선 49개이고 사이클이 없는지, Kruskal과 Prim의 총 비용이 같은지를 프로그램이 확인한다 (모두 OK).

## 측정 결과

| 경우 | MST 간선 수 | MST 전체 비용 | 메모리 | 실행시간 |
|---|---|---|---|---|
| 1. 희소 - 리스트 - Kruskal | 49 | 1,368 | 5,796 B | 6.34 us |
| 2. 밀집 - 리스트 - Kruskal | 49 | 264 | 27,796 B | 57.14 us |
| 3. 희소 - 행렬 - Prim | 49 | 1,368 | 11,192 B | 11.30 us |
| 4. 밀집 - 행렬 - Prim | 49 | 264 | 11,192 B | 11.95 us |

메모리 구성: Case 1 = 리스트 3,608 + 보조 2,188, Case 2 = 리스트 19,608 + 보조 8,188, Case 3·4 = 행렬 10,004 + 보조 1,188.
같은 그래프에서 Kruskal과 Prim의 MST 비용은 1,368과 264로 같았다. MST의 총 비용은 알고리즘과 상관없이 같고, 가중치가 같은 간선이 있으면 선택되는 간선 구성만 다를 수 있다.

## 분석

**희소 그래프와 밀집 그래프의 차이**: 같은 정점 50개에서 간선이 6배(100 → 600) 늘어나자 MST 비용은 1,368에서 264로 크게 줄었다. 고를 수 있는 간선이 많아져서 더 가벼운 간선으로 모든 정점을 연결할 수 있기 때문이다. 성능 면에서는 Kruskal + 리스트가 메모리 4.8배, 실행시간 9.0배로 커진 반면, Prim + 행렬은 메모리가 그대로이고 실행시간은 1.06배로 거의 같았다.

**인접 리스트와 인접 행렬의 메모리 차이**: 행렬은 간선 수와 상관없이 항상 10,004 B이고, 리스트는 간선 수에 비례해서 늘어난다. 그래프만 비교하면 희소 그래프에서는 리스트(3,608 B)가 행렬(10,004 B)의 약 36%이지만, 밀집 그래프에서는 리스트(19,608 B)가 행렬의 약 2배이다. 리스트는 간선마다 노드 2개(포인터 포함 16 B씩)를 쓰기 때문이다. Kruskal은 여기에 간선 배열과 Union-Find까지 필요해서, 간선이 약 220개를 넘으면 Kruskal + 리스트가 Prim + 행렬보다 메모리를 더 쓴다. 희소(5,796 B)는 행렬 조합(11,192 B)의 절반 정도이고, 밀집(27,796 B)은 2.5배였다.

**Kruskal과 Prim의 실행 특성**: Kruskal은 간선 중심 알고리즘이다. 모든 간선을 정렬해야 해서 시간이 간선 수 `E`에 따라 커지고(`O(E log E)`), 실험에서도 간선이 6배 늘자 시간이 9배 늘었다. 대신 간선이 적으면 정렬할 양이 적고 전체를 다 보지 않아도 되어서 빠르다. Prim은 정점 중심 알고리즘이다. 행렬에서 가장 작은 비용의 정점을 고르는 일을 정점 수만큼 반복하므로 시간이 `O(V²)`이고, 간선이 몇 개든 행렬 전체를 훑는 양이 같아서 희소와 밀집의 시간이 거의 같았다(11.30 us, 11.95 us).

**그래프 밀도의 영향**: 희소 그래프에서는 Kruskal + 리스트가 Prim + 행렬보다 시간이 약 1.8배 빠르고 메모리도 절반이다. 밀집 그래프에서는 반대로 Prim + 행렬이 시간이 약 4.8배 빠르고 메모리도 약 2.5배 적다. 이 실험에서 두 방법이 역전되는 지점은 간선 100개와 600개 사이이다. 따라서 간선이 적은 그래프는 Kruskal + 인접 리스트가, 간선이 많은 그래프는 Prim + 인접 행렬이 적합하다.

**참고**: 메모리 값은 64비트 환경(포인터 8 B) 기준이고, 32비트 환경에서는 리스트 노드가 더 작아져서 값이 달라진다. 실행시간은 컴퓨터와 컴파일 옵션에 따라 달라지지만, 시드 12345로 4번 반복해서 측정했을 때 각 경우의 값이 약 10% 안에서 일정했고 경우 사이의 순서도 같았다.
