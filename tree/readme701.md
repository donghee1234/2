# 인접 행렬과 인접 리스트의 성능 비교

정점 100개, 간선 100개(희소)와 4,000개(밀집) 그래프를 인접 행렬과 인접 리스트로 각각 구현해서 측정했다.
아래 수치는 `./graph_compare 12345` (시드 12345)로 실행한 결과이며, 같은 시드로 실행하면 똑같이 재현된다.

## 측정 방법

- **메모리**: `sizeof`로 계산했다. 난수 생성용 임시 배열과 코드 자체는 제외했다.
  - 인접 행렬 = `int matrix[100][100]` 40,000 B + 정점 수 `n` 4 B = 40,004 B
  - 인접 리스트 = 헤드 포인터 배열과 `n` 808 B + (노드 수 × 16 B). 노드 수는 간선 수의 2배(무방향)
- **비교 횟수**: 확인한 자료구조의 원소 수로 계산했다.
  - 행렬: 연결 확인과 삽입·삭제의 존재 확인은 `matrix[u][v]` 1회, 인접 정점 출력은 행 전체 100회
  - 리스트: u의 리스트를 차례로 확인한 노드 수. 삽입은 맨 앞에 넣으므로 중복 확인용 탐색만 센다. 삭제는 u의 리스트와 v의 리스트에서 각각 노드를 찾아야 해서 두 번 센다.
- **측정 대상**: 간선 삽입 20회, 삭제 20회, 연결 확인 50쌍, 인접 정점 출력 10개 정점. 네 경우 모두 같은 정점 쌍과 정점을 사용했다.
- 인접 행렬과 인접 리스트가 같은 그래프인지 삽입·삭제 전후에 코드로 검증했다 (모두 OK).

## 측정 결과

| 경우 | 메모리 | 삽입 | 삭제 | 연결 확인 | 인접 정점 출력 |
|---|---|---|---|---|---|
| 1. 희소 - 행렬 | 40,004 B | 20 | 20 | 50 | 1,000 |
| 2. 희소 - 리스트 | 4,008 B | 37 | 90 | 94 | 21 |
| 3. 밀집 - 행렬 | 40,004 B | 20 | 20 | 50 | 1,000 |
| 4. 밀집 - 리스트 | 128,808 B | 1,590 | 1,606 | 2,608 | 785 |

(비교 횟수는 합계이며, 1회당 평균은 삽입·삭제·연결 확인 기준 행렬은 항상 1회, 인접 정점 출력은 행렬 100회이다.
리스트는 희소에서 각각 1.85 / 4.50 / 1.88 / 2.10회, 밀집에서 79.50 / 80.30 / 52.16 / 78.50회이다.)

## 분석

**메모리**: 인접 행렬은 간선 수와 상관없이 항상 40,004 B이다. 인접 리스트는 간선 수에 비례해서 늘어난다. 희소 그래프에서는 리스트가 행렬의 약 1/10(4,008 B)이지만, 밀집 그래프에서는 노드마다 포인터가 붙어서 오히려 약 3.2배(128,808 B)로 커졌다. 계산해 보면 간선이 약 1,225개(전체 가능한 4,950개의 약 25%)를 넘으면 리스트가 행렬보다 메모리를 더 쓴다.

**간선 삽입·삭제와 연결 확인**: 행렬은 `matrix[u][v]`를 바로 확인하므로 그래프 밀도와 상관없이 항상 1회이다. 리스트는 u의 리스트를 차례로 확인해야 해서, 정점의 평균 차수에 비례한다. 희소 그래프는 차수가 평균 2라서 1.85~4.50회로 차이가 작지만, 밀집 그래프는 차수가 평균 80이라서 50~80회로 행렬보다 훨씬 많다. 삭제는 두 리스트를 모두 탐색해야 해서 삽입보다 비교가 더 많다.

**인접 정점 출력**: 행렬은 그 행의 100칸을 모두 확인해야 하므로 정점당 항상 100회이다. 리스트는 실제 이웃 수만큼만 확인한다. 희소 그래프에서는 정점당 2.10회로 행렬보다 약 48배 적었다. 밀집 그래프에서는 이웃이 평균 80개라서 78.50회로 거의 차이가 없었다.

**희소 그래프에서의 차이**: 인접 리스트가 메모리를 약 90% 아끼고, 인접 정점 출력도 훨씬 빠르다. 대신 삽입·삭제·연결 확인은 행렬이 조금 더 적게 비교하지만 차이는 몇 회 수준이라 크지 않다. 전체적으로 리스트가 유리하다.

**밀집 그래프에서의 차이**: 인접 행렬이 메모리도 더 적고, 삽입·삭제·연결 확인에서 비교 횟수가 수십 배 적다. 인접 정점 출력만 비슷하다. 전체적으로 행렬이 유리하다.

## 어떤 경우에 무엇을 쓰면 좋은가

- **인접 리스트**: 간선이 적은 희소 그래프이거나, 정점의 이웃을 자주 순회하는 경우(그래프 탐색 등). 정점이 아주 많은 그래프에서는 행렬이 V×V로 커지기 때문에 특히 리스트가 필요하다.
- **인접 행렬**: 간선이 많은 밀집 그래프이거나, 두 정점이 연결됐는지 확인하고 간선을 삽입·삭제하는 작업이 많은 경우.

**참고**: 이 결과는 `int` 행렬 기준이다. 행렬을 1바이트 자료형으로 만들면 행렬이 10,004 B로 줄어서 리스트가 불리해지는 간선 수가 약 290개로 낮아진다. 또 비교 횟수는 실제 실행 시간과 완전히 같지는 않다. 리스트는 노드가 메모리에 흩어져 있어서 노드 하나를 읽는 비용이 행렬보다 더 클 수 있다.
