# 순차 탐색, 이진 탐색 트리(BST), AVL 트리의 성능 비교

`search3.c` 실행 결과(아래 수치는 실행 예시 1회 기준이며, 실행할 때마다 난수가 달라져 수치는 변하지만 경향은 비슷하다)를 바탕으로 분석한다.

## 측정 결과

- 생성 시도 100회 중 **실제로 저장된 서로 다른 값 : 95개**, 중복으로 삽입되지 않은 값 : 5개

| 항목 | 배열 | BST | AVL |
|---|---|---|---|
| 생성 과정 총 비교 횟수 | 4,579 | 634 | 535 |
| 자료구조 크기/높이 | 길이 95 | 높이 13 | 높이 8 |

| 탐색(50회) | 총 비교 횟수 | 평균 비교 횟수 |
|---|---|---|
| 순차 탐색 | 4,440 | 88.80 |
| BST 탐색 | 406 | 8.12 |
| AVL 탐색 | 329 | 6.58 |

## 1. BST와 AVL 트리의 높이가 다른 이유

같은 95개의 값을 같은 순서로 삽입했는데도 BST 높이는 13, AVL 높이는 8로 차이가 크다. BST는 삽입 순서에 따라 모양이 그대로 결정되기 때문에, 값이 어느 정도 정렬된 순서로 들어오면 한쪽으로 치우친 모양이 되어 높이가 불필요하게 커진다. 반면 AVL 트리는 노드를 삽입할 때마다 왼쪽과 오른쪽 서브트리의 높이 차이가 1을 넘지 않도록 회전을 수행해서 트리를 항상 균형 잡힌 모양으로 유지한다. 그 결과 노드 개수가 같아도(95개) AVL의 높이가 log₂(95) ≈ 6.6에 가까운 8로 유지되는 반면, BST는 삽입 순서의 영향을 그대로 받아 13까지 높아졌다.

## 2. 트리의 높이가 탐색 비교 횟수에 미치는 영향

BST/AVL 탐색에서 한 번의 비교는 탐색 범위를 왼쪽 또는 오른쪽 자식으로 좁히는 역할을 하므로, 탐색에 필요한 최대 비교 횟수는 트리의 높이와 거의 같다. 실제로 BST 탐색 평균(8.12)은 BST 높이(13)보다 작고, AVL 탐색 평균(6.58)은 AVL 높이(8)보다 작은데, 이는 트리 전체를 다 내려가지 않고 탐색 중간에 값을 찾거나(성공) 더 얕은 깊이에서 끝(실패)나는 경우가 많기 때문이다. 핵심은 높이가 낮을수록 탐색 비교 횟수도 함께 줄어든다는 점이며, 높이가 13에서 8로 약 60% 수준으로 줄어들자 평균 비교 횟수도 8.12에서 6.58로 비슷한 비율로 줄었다. 반면 순차 탐색은 트리 구조와 무관하게 항상 데이터 개수(95)에 비례하기 때문에 평균 88.80회로 압도적으로 느리다.

## 3. 세 자료구조의 생성 비용과 탐색 비용 비교 분석

생성 비용만 보면 배열(4,579회)이 BST(634회)나 AVL(535회)보다 훨씬 크다. 이는 배열이 중복 확인을 위해 이미 저장된 값 전체를 하나씩 비교해야 하는 반면(순차 탐색과 동일한 방식), BST와 AVL은 트리 구조 덕분에 한 번 비교할 때마다 비교 대상을 절반씩 줄여나갈 수 있기 때문이다. 흥미로운 점은 AVL의 생성 비용(535회)이 BST(634회)보다도 오히려 더 적다는 것이다. 이는 AVL이 삽입 중간중간에도 트리를 균형 잡힌 상태로 유지하기 때문에, 삽입 위치를 찾기 위해 내려가는 경로 자체가 BST보다 짧기 때문이다. 즉 AVL은 회전이라는 추가 작업을 하면서도(이 비교 횟수는 측정에 포함되지 않았지만), 데이터 값 비교 측면에서는 생성 비용과 탐색 비용 모두 BST보다 우수했다.

종합하면, 데이터 개수가 많고 반복적으로 탐색을 수행하는 상황이라면 AVL 트리가 생성과 탐색 양쪽에서 가장 효율적이다. BST는 AVL보다 생성 비용은 비슷하게 적지만, 삽입 순서에 따라 트리가 치우칠 경우 탐색 성능이 크게 떨어질 위험이 있다. 배열(순차 탐색)은 생성 비용과 탐색 비용 모두 다른 두 구조에 비해 월등히 크므로, 데이터 양이 많아질수록 가장 비효율적인 방법이 된다.
