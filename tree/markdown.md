1. 메모리 사용량 비교
   연결 자료구조 방식은 트리 모양과 상관없이 항상 노드 수에 비례해서 메모리를 사용합니다. 반면 배열 방식은 트리 모양에 따라 사용량이 크게 달라지기 때문에 완전 이진트리일 때는 인덱스가 빈틈없이 채워져서 배열 방식이 훨씬 적은 메모리를
   쓰지만 편향 이진트리일 때는 부모 인덱스 × 2 규칙 때문에 인덱스가 기하급수적으로 커져서 대부분의 공간이 낭비됩니다 그러므로 트리가 완전 이진트리에 가까우면 배열 방식이 유리하고 트리가 한쪽으로 치우칠수록 연결 자료구조 방식이 유리합니다

   | 트리 형태 | 배열 방식 | 연결 자료구조 방식 |
   |---|---|---|
   | 일반 이진트리 | 15 byte | 168 byte |
   | 완전(포화) 이진트리 | 8 byte | 168 byte |
   | 편향 이진트리 | 65 byte | 168 byte |

2. 부모, 자식, 형제 노드 조회 비교
   자식 찾기: 두 방식 모두 바로 접근 가능해서 속도 차이 X
   부모,형제 찾기: 배열 방식은 계산만으로 바로 부모를 찾을 수 있지만 연결 자료구조 방식은 노드가 부모를 가리키는 포인터가 없어서 루트부터 트리를 다시 훑어야 부모를 찾을 수 있습니다.
   따라서 부모, 형제 노드를 조회하는 속도는 배열 방식이 더 효율적이지만 완전 이진트리에 가까울 때만 유효하고 편향 트리처럼 형태가 나쁘면 배열 방식은 메모리 낭비가 너무 커서 실용적이지 않습니다.
