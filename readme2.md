# 삽입 정렬과 쉘 정렬의 성능 비교

무작위 정수(0~1,000,000)로 데이터 크기 n = 1,000 / 2,000 / 4,000 / 8,000 / 16,000 / 20,000에서 삽입 정렬, 쉘 정렬(기본 간격 n/2, n/4, ..., 1), 쉘 정렬(Knuth 간격 1, 4, 13, 40, ...)의 비교 횟수를 측정했다.
아래 수치는 `./shell_compare 12345`(시드 12345)로 실행한 결과이며, 같은 시드면 같은 데이터가 만들어진다.

## 측정 방법

- 각 데이터 크기마다 원본 데이터를 한 번 만들고, 세 방법 모두 같은 원본의 복사본을 오름차순으로 정렬했다.
- 비교 횟수는 데이터 값끼리 비교한 횟수(`a[j] > current`)이다. 결과와 상관없이 1회로 세고, 반복문의 인덱스·종료 조건 검사, 데이터 생성, 배열 복사는 제외했다.
- 모든 정렬 결과가 오름차순인지, 세 방법의 결과가 서로 같은지 프로그램이 검증한다 (모두 OK).
- Knuth 간격은 데이터 크기보다 작은 가장 큰 간격부터 역순으로 적용했다.

## 측정 결과

| n | 삽입 정렬 | 쉘 정렬 (기본 간격) | 쉘 정렬 (Knuth) |
|---|---|---|---|
| 1,000 | 249,209 | 15,025 | 14,324 |
| 2,000 | 989,777 | 35,963 | 32,803 |
| 4,000 | 3,940,812 | 82,993 | 79,341 |
| 8,000 | 16,124,650 | 203,815 | 170,315 |
| 16,000 | 64,041,306 | 484,727 | 444,272 |
| 20,000 | 99,543,799 | 607,539 | 570,159 |

n이 2배가 될 때 비교 횟수가 늘어난 배율은 다음과 같다.

| n 증가 | 삽입 정렬 | 쉘 정렬 (기본) | 쉘 정렬 (Knuth) |
|---|---|---|---|
| 1,000 → 2,000 | 3.97배 | 2.39배 | 2.29배 |
| 2,000 → 4,000 | 3.98배 | 2.31배 | 2.42배 |
| 4,000 → 8,000 | 4.09배 | 2.46배 | 2.15배 |
| 8,000 → 16,000 | 3.97배 | 2.38배 | 2.61배 |

## 분석

**데이터 크기 증가에 따른 비교 횟수 변화**: 삽입 정렬은 n이 2배가 되면 비교 횟수가 약 4배가 된다(3.97~4.09배). 비교 횟수가 n²에 비례한다는 뜻이고, n = 20,000에서 약 1억 회로 이론값 n²/4 = 약 1억과 거의 같다. 쉘 정렬은 n이 2배가 될 때 약 2.2~2.6배만 늘어서(n의 약 1.1~1.4제곱에 비례) 두 간격 수열 모두 삽입 정렬보다 훨씬 완만하게 증가했다.

**삽입 정렬과 쉘 정렬의 성능 차이**: 삽입 정렬 대비 쉘 정렬의 비교 횟수는 n = 1,000에서 약 17배 적었고, n = 20,000에서는 약 164배(기본 간격)~175배(Knuth) 적었다. 데이터가 커질수록 차이가 더 벌어진다. 삽입 정렬은 원소를 한 칸씩만 옮기기 때문에, 무작위 데이터에서 서로 순서가 뒤바뀐 쌍(약 n²/4개)을 하나씩 해결하는 만큼 비교가 필요하다. 반면 쉘 정렬은 큰 간격으로 멀리 떨어진 원소를 한 번에 크게 이동시켜 뒤바뀐 쌍을 빠르게 줄이고, 간격이 작아질 때는 이미 데이터가 거의 정렬되어 있어서 삽입 정렬이 원소당 비교 1~2회 정도로 끝난다. 마지막 단계(간격 1)가 일반 삽입 정렬인데도 전체 비용이 작은 이유이다.

**기본 간격과 Knuth 간격의 성능 차이**: Knuth 간격이 모든 크기에서 기본 간격보다 비교 횟수가 적었고, 시드 12345에서는 약 4~16% 적었다. 시드를 바꿔 200번 반복해서 확인했을 때도 Knuth가 더 적었던 경우가 크기별로 195~200번이었고, 평균 8~14% 적었다. 다만 이 차이는 삽입 정렬과 쉘 정렬의 차이(약 17~175배)에 비하면 훨씬 작다. 무작위 데이터에서는 기본 간격의 약점이 크게 드러나지 않기 때문이다.

**간격 수열이 쉘 정렬의 성능에 영향을 미치는 이유**:
- **간격 사이의 관계**: 기본 간격(n/2, n/4, ...)은 앞 간격이 뒤 간격의 배수인 경우가 많아서, 큰 간격 단계에서는 짝수 위치와 홀수 위치처럼 서로 다른 그룹의 원소가 섞이지 않는다. 이런 원소들은 간격이 1이 되는 마지막 단계에서야 처음 비교되므로 마지막 단계에 순서가 뒤바뀐 쌍이 많이 남아 비교가 늘어난다. Knuth 간격(1, 4, 13, 40, ...)은 서로 배수 관계가 아니라서 이전 단계에서 나뉘어 있던 원소들이 다음 단계에서 섞이기 때문에 단계마다 정렬 상태가 더 효율적으로 좋아진다.
- **단계 수**: 각 단계는 최소 n번 가까이 비교해야 하는데, Knuth 간격은 3배씩 줄어서 단계 수가 적다. n = 20,000에서 기본 간격은 14단계, Knuth는 9단계였다 (n = 1,000에서는 9단계와 6단계).
- **최악의 경우**: 기본 간격은 최악의 경우 n²에 비례하고, Knuth 간격은 n^1.5에 비례하는 것으로 알려져 있다. 이번 실험은 무작위 데이터만 사용해서 최악의 경우를 직접 확인하지는 못했지만, 위 이유들로 Knuth 간격이 일관되게 더 적게 비교했다.

**결론**: 삽입 정렬은 데이터가 커질수록 n²으로 급격히 느려지고, 쉘 정렬은 간격을 줄여 가며 정렬하는 것만으로 비교 횟수를 수십~백 배 줄인다. 같은 쉘 정렬이라도 간격 수열에 따라 성능이 달라지며, 서로 배수 관계가 아니고 단계 수가 적은 Knuth 간격이 더 유리했다.
